# LayPipe artwork authorization and IPFS API

The upload is intentionally split because Vercel Functions reject request bodies
above 4.5 MB while LayPipe accepts artwork up to 5 MB. The browser never sends
the raw file in a LayPipe Function request. A wallet-authorized, 60-second Pinata
URL stages it; the final Function retrieves the staged bytes, verifies, decodes,
sanitizes, and pins the permanent image and metadata.

Every challenge is an EIP-191 message. The opaque `challenge` is an HMAC-signed,
five-minute token containing the wallet, action, exact request digest, nonce, and
expiry. Upstash consumes the nonce with `SET NX`, so a signature cannot be replayed.
Production fails closed if Upstash is unavailable.

Set `IPFS_PINNING_ENABLED=true` only when production Pinata, gateway, challenge,
and Redis configuration has been exercised. The challenge, stage, and pin routes
all honor this server-side kill switch.

## Browser contract

1. Hash the original file with SHA-256 and calculate the canonical stage digest
   from `{action,wallet,fileName,mimeType,size,fileSha256}`.
2. `POST /api/auth/challenge`:

   ```json
   {"wallet":"0x...","action":"stage","contentDigest":"64 lowercase hex"}
   ```

   Response: `{challenge,message,expiresAt}`. Sign `message` with
   `personal_sign` / EIP-191.
3. `POST /api/ipfs/stage`:

   ```json
   {
     "wallet":"0x...",
     "fileName":"coin.png",
     "mimeType":"image/png",
     "size":1234,
     "fileSha256":"64 lowercase hex",
     "challenge":"...",
     "signature":"0x..."
   }
   ```

   Response: `{uploadUrl,expiresAt}`. Immediately `POST` multipart directly to
   `uploadUrl` with `network=public` and `file=<original File>`. Pinata responds
   with `{data:{id,cid,...}}`; retain `id` and `cid` only for the final request.
4. Calculate the canonical pin digest from
   `{action,wallet,stagedCid,stagedFileId,fileSha256,metadata}`, request a new
   `action: "pin"` challenge, and sign it.
5. `POST /api/ipfs/pin` with JSON:

   ```json
   {
     "wallet":"0x...",
     "stagedCid":"bafy...",
     "stagedFileId":"Pinata file UUID",
     "fileSha256":"64 lowercase hex",
     "metadata":{"name":"...","symbol":"...","description":"...","external_url":"https://laypipe.fun/","attributes":[{"trait_type":"launch_provider","value":"laypipe"},{"trait_type":"chain","value":"robinhood"},{"trait_type":"fee_mode","value":"self-burn"}]},
     "challenge":"...",
     "signature":"0x..."
   }
   ```

   The server requires the exact canonical metadata draft generated by
   `normalizeMetadataDraft`. Success returns exactly:

   ```json
   {
     "image":{"cid":"bafy...","uri":"ipfs://bafy...","gatewayUrl":"https://gateway.pinata.cloud/ipfs/bafy..."},
     "metadata":{"cid":"bafy...","uri":"ipfs://bafy...","gatewayUrl":"https://gateway.pinata.cloud/ipfs/bafy..."},
     "metadataDocument":{"name":"...","symbol":"...","description":"...","image":"ipfs://bafy...","external_url":"...","attributes":[]}
   }
   ```

The client must deep-compare `metadataDocument` to its locally rebuilt document
before requesting a PIPEDOG allowance.

## Required production configuration

- `PINATA_JWT`: server-only Pinata JWT with file read/write/delete access.
- `IPFS_PINNING_ENABLED=true`: explicit production publishing kill switch.
- `IPFS_GATEWAY_BASE_URL`: dedicated HTTPS Pinata gateway, either
  `https://name.mypinata.cloud` or `https://name.mypinata.cloud/ipfs`.
- `WALLET_CHALLENGE_SECRET`: at least 32 random bytes; never a public variable.
- `UPSTASH_REDIS_REST_KV_REST_API_URL`
- `UPSTASH_REDIS_REST_KV_REST_API_TOKEN`
- `NEXT_PUBLIC_SITE_URL=https://laypipe.fun`
- `CRON_SECRET`: at least 32 random characters for the stale-stage cleanup route.

For local portability, `UPSTASH_REDIS_REST_URL` and
`UPSTASH_REDIS_REST_TOKEN` are accepted as fallbacks. Local development can run
without Upstash; production cannot.

## Direct dependencies

- `sharp@0.35.3` for bounded image decoding and deterministic WebP re-encoding.
- `multiformats@13.4.1` for real CID parsing and CIDv1 normalization.
- `viem@2.55.13` for EIP-191 signature verification.

No Pinata or Upstash SDK is required; both integrations use their documented
HTTPS APIs with native `fetch`.

## Abandoned-stage cleanup

Run `GET` or `POST /api/ipfs/cleanup` with
`Authorization: Bearer $CRON_SECRET` on a bounded recurring schedule (or invoke
it manually). The route asks Pinata only for files tagged
`laypipe_stage=true`, validates all LayPipe staging tags, and deletes at most
100 raw staging files older than one hour per invocation. It never selects
`laypipe=token-artwork` or `laypipe=token-metadata` permanent pins. Pagination
is capped at 10 pages and malformed pages fail closed. A nonzero `failed` count
returns HTTP 502 so the scheduler can retry; `truncated: true` means invoke the
route again. No `vercel.json` schedule is committed so the cadence can match the
chosen Vercel plan.
